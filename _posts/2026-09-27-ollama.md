How many times have I wasted time manually copying raw chat logs from browser interfaces, pasting them into text files, and cluttering my vault with messy, unformatted text? If I want a seamless bridge to capture AI conversations from my browser and turn them into clean, structured notes inside Obsidian—while keeping everything completely private—running a local model is the way to go.

In this article, I will explore how to turn a Fedora Linux machine into a local processing hub using Ollama, install Obsidian, integrate them directly, and bridge browser chats into notes.

However, before diving into local Large Language Models (LLMs), it is important to understand the hardware realities. If I were running older hardware, entry-level ultrabooks without dedicated graphics, or systems with limited resources, forcing a heavy local model would lead to frustratingly slow performance. For those use cases, leveraging a cloud API alternative (such as Google AI Studio, which I will cover in a follow-up post) is often a much smoother choice.

&nbsp;

##### **Hardware Reality Check: Is Local AI Right for You?**

Local model inference is fundamentally memory- and compute-bound. Before downloading gigabytes of model files, I keep these guidelines in mind:

* The Graphic / Processor Bottleneck: Running models locally smoothly requires a modern multi-core processor and a decent amount of RAM or GPU VRAM. If a machine struggles with heavy multitasking or lacks proper graphics acceleration, local LLMs will crawl at a few tokens per second.

* The Disk Space Trap: AI models are multi-gigabyte files, and they accumulate quickly as different variants are tested.

    * A lightweight model (like 3B parameters) takes around 2 GB of disk space.

    * A standard mid-tier model (like Qwen 2.5 7B) takes roughly 4.7 GB.

    * Larger models (14B or 32B) easily range from 10 GB to 20 GB+.

    * Tip: I always provision at least 15 to 20 GB of free NVMe space just to safely manage the initial model library and temporary download layers.

If the system checks out and there is enough disk headroom, it's time to get it running.

&nbsp;

##### **Step 1: Installing and Starting Ollama on Fedora**

Ollama makes managing open-weight models on Linux straightforward.

* **Installation**

Open terminal and install Ollama via DNF:

```bash
sudo dnf install ollama
```

* **Enable and Start the Service**

To ensure the daemon runs and stays active in the background:

```bash
sudo systemctl enable --now ollama
```

* **Pull an Efficient Model**

To find and explore available models, I check the official Ollama Library ([ollama.com/library](https://ollama.com/library)), where dozens of open-weight models (such as Llama, Qwen, Mistral, and Gemma) are cataloged with their respective sizes and parameter variants.

In a separate terminal, I download a well-balanced model like qwen2.5:7b (~4.7 GB):

```bash
ollama run qwen2.5:7b
```
Once downloaded, there is a local REST API running at http://localhost:11434.

&nbsp;

##### **Step 2: Installing Obsidian on Fedora**

To manage the notes locally using plain Markdown files, I install Obsidian. The cleanest approach on Fedora is via Flatpak:

```bash
flatpak install flathub md.obsidian.Obsidian
```

This keeps the application sandboxed while allowing full read/write access to my chosen vault directory on the local filesystem.

&nbsp;

##### **Step 3: Connecting Ollama to Obsidian & Bringing Browser Chats In**

To solve the friction of AI-assisted note-taking practically, I bridge the workflow using community tools:

1. Inside Obsidian: I install a plugin like Text Generator to interact directly with the local Ollama instance without cluttering the workspace.
2. From the Browser to Obsidian: When using web-based interfaces to chat, I am not locked into a single browser. Thanks to standard web extension protocols, tools work seamlessly across Firefox, LibreWolf, or Chromium-based browsers, allowing me to export or format clean Markdown directly into my Obsidian vault without manual copy-pasting.

&nbsp;

##### **Conclusion & What's Next**

Running Ollama locally gives me a robust, private assistant on Fedora. However, if hardware isn't suited for local inference, don't worry: in my next article, I will explore the cloud alternative, showing how to hook up a free Google AI Studio API key to Obsidian for instant, zero-footprint workflows.
